# Remote++

增强 NVDA 远程访问功能，为高级用户提供更高效的操作体验。

## 功能

### 连接管理器

快速保存、整理和连接常用的远程会话。

* 使用分组整理连接
* 按名称或主机搜索连接
* 从列表一键连接
* 复制连接链接到剪贴板

### 交换控制模式

在控制另一台计算机和被控制之间即时切换，无需断开连接。

### 连接到默认服务器

一键连接到已配置的自动连接服务器。

## 连接管理器

连接管理器提供了一个便捷的界面来管理您的远程连接。

### 列表快捷键

| 操作 | 快捷键 |
|------|--------|
| 以反向模式连接 | `Shift+回车` |
| 上移连接 | `Alt+上光标` |
| 下移连接 | `Alt+下光标` |
| 编辑连接 | `F2` |
| 删除连接 | `Delete` |
| 全选 | `Ctrl+A` |
| 复制链接 | `Ctrl+C` |

### 上下文菜单

右键单击连接可访问更多选项：

* 连接 / 以反向模式连接
* 编辑
* 复制链接
* 设置为自动连接
* 上移 / 下移
* 删除


## 快捷键

| 命令 | 手势 |
|------|------|
| 打开连接管理器 | `NVDA+Control+Shift+N` |
| 交换控制模式 | `NVDA+Control+Shift+W` |
| 连接到默认服务器 | 无 |

## 菜单项

所有功能也可通过 NVDA 远程访问菜单使用:

* 连接管理器...
* 交换控制模式
* 连接到默认服务器（仅在已配置自动连接时显示）

## 要求

* NVDA 2026.1 或更高版本，需启用内置远程访问功能

## 安全性
为最大限度确保安全并防止意外访问，该插件在安全桌面（如 UAC 提示、Windows 登录界面）上将被禁用。

## 低延迟音频

低延迟音频通过 `NVDARemoteAudioServer` 转发被控计算机的声音。音频服务器
自动使用当前 Remote 连接的主机，端口固定为 `6838`，并复用 Remote 密钥。
建立连接时音频默认关闭，连接编辑器中不包含音频设置。

Remote Access 菜单提供两个独立选项：

* 收听远程系统声音（Windows 默认输出设备的声音）
* 收听远程麦克风

这两个选项只在控制方可用。启用后，控制方会请求被控方启动对应的采集；
两路声音可以同时启用并在被控方混合。被控方需要安装 Remote++ 及随附的
音频模块。如果对方使用旧版 Remote 或没有安装 Remote++，
音频请求会超时或报告不可用，但 Remote 连接不会断开。当前版本不分配音频
快捷键。

两台计算机都必须通过 NVDA 内置的“远程访问”建立连接。通过 TeleNVDA 或旧版
NVDA Remote 插件建立的连接不会接入 Remote++ 的音频控制，即使两端安装了相同
版本的 Remote++ 也不能开启音频。请求超时时，请检查被控端实际使用的远程客户端。

被控方确认 NVDA 使用默认输出设备和有效语音合成器，且控制方正在收到音频时，
才会暂停该音频发布者的 Remote 语音重放，避免重复朗读。选择“无语音”、将语音
音量设为零、指定其他输出设备或对方未提供确认信息时，保留原有语音。音量变化
会在每次转发朗读时检查。第二台被控计算机加入频道时，两路音频会自动关闭，
所有被控计算机仍正常回放语音和提示音。

约半秒未收到有效音频时，会恢复 Remote 语音，并保持监听等待音频恢复；正常的
静音间隔不会关闭音频或反复报错。关闭音频、采集失败或被控方重新加载插件时，
也会自动恢复 Remote 语音。
Remote 的“静音远程”和切回本机时的自动静音也会应用于音频收听；取消静音后
继续播放实时声音，不会补播静音期间积压的音频。

音频模块将 16 位 PCM 压缩为 Opus，默认采用 48 kHz 立体声、96 kbps、每包 10 毫秒。
解码后以 5 毫秒块播放。实际延迟还取决于
设备周期和网络；音频协议不提供加密，请使用可信网络或 VPN。

音频模块在 NVDA 内运行，使用自带的 comtypes、pycaw、WavePlayer，以及随插件附带的
x64 libopus DLL，无需额外安装运行环境。采样率和声道转换
由 Windows 音频引擎处理。默认采集设备发生变化或断开时，音频停止并报错，重新
开启对应菜单项即可使用新设备。静音或媒体中断时丢弃旧音频，避免恢复后补播。

### 音频设置

控制方可以在 **NVDA 设置 → Remote++** 中调整四个选项：

* **播放缓冲**：最小缓冲（默认）、10、20、40、80 毫秒。最小缓冲尽快播放；
  增加缓冲可以缓解到包不均匀造成的断续，但声音会相应延后。此数值不是总延迟。
* **音频比特率**：64、96（默认）、192 kbps。降低比特率可节省带宽，但会损失细节。
  对应音频数据约 8、12、24 KB/s，实际网络流量还包含协议开销。这是混音后整条流的总比特率。
* **音频声道**：单声道、立体声（默认）。单声道在低比特率下可保留更多细节，
  但相同比特率下不会将流量减半。
* **传输模式**：低延迟，每包 10 毫秒（默认）；均衡，每包 20 毫秒。
  均衡模式可减少包数量和协议开销，但会增加等待时间。

采样率固定为 48 kHz。最小缓冲不代表零延迟，较小的播放缓冲也不能消除整包到达前的等待。

设置适用于所有连接，包括通过链接建立的连接，并与连接管理器的偏好保存在一起，
不随 NVDA 配置文件切换。被控方无需调整自己的设置，会按控制方协商的音质采集。

点击“应用”或“确定”后保存并生效。正在收听时会短暂重启音频，保留已开启的系统
声音和麦克风；音频关闭时只保存设置，不自动开启。仅改变选项或点击“取消”不会
应用；已经点击“应用”的更改不会被随后“取消”撤销。连接音频期间修改的设置会在
当前请求成功后应用最新值；请求失败时不自动重试。Remote 主连接不受影响。

双方都必须升级到支持 Opus 的 Remote++，不再回退到 PCM。旧版连接仍可正常远程控制和朗读。
升级时保留原有播放缓冲和单／双声道偏好，新增设置使用默认值。无效的已保存值会回退到默认值。
同一音频通道同时由一位控制方使用，其他控制方需等待其关闭音频或断开连接。
使用音频时，Remote 通道中只能有一台被控计算机。
